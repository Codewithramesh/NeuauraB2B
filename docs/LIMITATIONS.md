# Known limitations and remaining work

- A real local LLM is installed and tested: Ollama with Qwen3 4B. Real transcription, structured extraction, exact evidence, task approval, persistence and the HTTP simulator pass on synthetic English audio. This is a small-model smoke test, not a broad accuracy evaluation. Managers must review categories, interpretations and suggestions against source evidence.
- Real speech recognition passed using macOS-synthesized English audio and the downloaded tiny.en model. Physical MacBook microphone permission/quality is NOT VERIFIED. Browser MediaRecorder itself passed with Chrome's simulated microphone. A synthetic microphone is not a substitute for physical-device acceptance.
- Phone layout/navigation is tested at 390 × 844 in Chrome. Physical iPhone Safari/Android Chrome capture, secure phone connection and OS permissions are NOT VERIFIED. Setup is documented; no mobile background recording guarantee.
- Only one API process/worker is supported. The 8 GB Mac uses one loaded AI model, an 8,192-token context, disabled thinking, and a one-minute idle model timeout. Longer recordings may take substantial time; full-length and noisy-room quality is not verified. In-process locks/limits are insufficient for multiple replicas. Upload bodies are memory bounded by the configured encoded limit; fleet quotas and distributed upload storage need development.
- SQLite/local file persistence is tested. PostgreSQL is architecturally supported through SQLAlchemy but driver/deployment behavior is NOT VERIFIED. No paid hosting or cloud deployment was created.
- Tiny English speech accuracy in noisy venues, accents and multi-party conversation needs real evaluation. No diarization, speaker identity, translation or Hindi evaluation. CPU int8 is tested; native Metal/GPU providers are extension points.
- Quote/schema checks reject fabricated excerpts and invalid timestamps. They cannot guarantee the semantic accuracy of summaries, confidence, recommendations, categorization or inferred customer intent. A manager must review evidence. Confidence is an uncalibrated model estimate.
- Current session metadata uses a trusted server creation clock. Optional `captured_at` is a separately labeled, device-reported clock and is not used for retention. Client duration is not used; decoded duration is measured. Real-time streaming/Bluetooth and physical provisioning are future adapters, not completed integrations.
- Devices use manual one-time credential provisioning and revocation. No automatic token rotation, mTLS, signed firmware or OTA updates. Register a replacement device and revoke the old one to rotate today.
- Initial setup provisions a single business workspace/admin through the UI. Database tenant isolation is tested with a second tenant fixture, but multi-workspace invites, role UI, SSO/MFA and password recovery are not built.
- API history is paginated. Insight/task list UI currently reads at most 1,000 rows; aggregation reads a tenant's complete records in memory. Revisit query strategies for large datasets.
- Retention executes hourly while the worker runs, not continuously while the app is stopped. Audit events have no separate expiry. SQLite/SSD/backups do not promise secure physical erasure.
- The setup/status UI is not a formal accessibility certification. Keyboard modal focus containment, reduced motion, semantic controls, chart data tables and responsive navigation are implemented and partially checked.
